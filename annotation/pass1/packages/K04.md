## Research question
How does Ridgeline-FT compare with Plainweave-FT in pass@1 on Quillbench?

## Methods summary
Ridgeline-FT fine-tunes a code model with an execution-feedback curriculum that orders training problems by the failure rate of the model's own samples. Plainweave-FT is standard supervised fine-tuning on the same data. Both start from the same 1.3B-parameter base model, Fernleaf-1.3B, which is also reported without fine-tuning.

## Experimental setup
Both recipes fine-tune Fernleaf-1.3B on the same 85,000 problem–solution pairs, each with 8 random seeds (seeds 0–7); seed i fixes data order and initialization for both recipes, so seed-level scores are paired. Evaluation uses greedy decoding on all 420 Quillbench problems (Python, hidden unit tests). The analysis plan pre-specified two endpoints for Ridgeline-FT vs Plainweave-FT, pass@1 (primary) and compile rate (secondary), and controls the family-wise error rate across these two tests with the Holm–Bonferroni procedure at α = 0.05.

## Experiments and comparisons
- `exp1`: Ridgeline-FT vs Plainweave-FT on Quillbench (420 problems)
  - comparison `exp1/cmp1`: Ridgeline-FT vs Plainweave-FT, pass@1 (primary endpoint)
  - comparison `exp1/cmp2`: Ridgeline-FT vs Plainweave-FT, compile rate (secondary endpoint)

## Statistical tests
- `S1` for comparison `exp1/cmp1`: paired t-test; two-sided; paired; n=8 random seeds (paired by seed); t=0.97 (df=7); Holm-adjusted p = 0.36; 95% CI [-0.75, 1.79] for mean paired difference in pass@1 (Ridgeline-FT − Plainweave-FT), percentage points; unadjusted 95% CI; alpha=0.05; adjustment: Holm–Bonferroni across the two pre-specified endpoints (S1 pass@1, S2 compile rate); note: Unadjusted p = 0.36 (unchanged by the Holm step-down).
